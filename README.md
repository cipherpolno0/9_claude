# เว็บไซต์กองบริหารทะเบียนและวัดผล

เว็บรวม 9 ระบบงานการศึกษาและการปกครองคณะสงฆ์ไว้ในเว็บเดียว
กติกาของโครงการอยู่ในไฟล์ `CLAUDE.md`

## วิธีเปิดดูบนเครื่องตนเอง

1. ติดตั้ง Node.js รุ่น 20 ขึ้นไป (ดาวน์โหลดจาก https://nodejs.org เลือกรุ่น LTS)
2. เปิดโปรแกรม Terminal (Windows: PowerShell) แล้วเข้าโฟลเดอร์โครงการนี้
3. พิมพ์ `npm install` แล้วรอจนเสร็จ (ทำครั้งแรกครั้งเดียว)
4. พิมพ์ `npm run dev`
5. เปิดเบราว์เซอร์ไปที่ http://localhost:3002
   (โครงการนี้กำหนดให้ใช้พอร์ต 3002 เสมอ ถ้าขึ้นว่าพอร์ตถูกใช้อยู่ แปลว่ามีหน้าต่าง `npm run dev` เปิดค้างไว้อีกหน้าต่างหนึ่ง ให้ปิดหน้าต่างนั้นก่อน)

## เชื่อมฐานข้อมูล Supabase

โครงการ Supabase ที่ใช้: `ukdlgujfongdesbbnblm` (Singapore)
migration ของบทที่ 2–7 และข้อมูลทดสอบ (เขตปกครอง ประเภทตำแหน่ง จศป.) ถูกรันลงโครงการนี้แล้ว

สิ่งที่ต้องทำบนเครื่องตนเอง (ครั้งเดียว):

1. คัดลอกไฟล์ `.env.example` เป็นชื่อ `.env.local` (สองค่าแรกเติมไว้ให้แล้ว)
2. เติมค่า `SUPABASE_SECRET_KEY` จากหน้า Project Settings > API Keys > Secret keys ของ Supabase
   - ห้ามส่งค่านี้ให้ผู้อื่น และห้ามนำไฟล์ `.env.local` ขึ้น GitHub
3. ใน Supabase เปิด Authentication > URL Configuration แล้วตั้ง
   - Site URL: `http://localhost:3002`
   - Redirect URLs: เพิ่ม `http://localhost:3002/**`
   (ใช้กับลิงก์ตั้งรหัสผ่านใหม่ในอีเมล เมื่อขึ้นเว็บจริงให้เพิ่มที่อยู่เว็บจริงด้วย)
4. พิมพ์ `npm install` แล้ว `npm run seed:test-users` เพื่อสร้างบัญชีทดสอบ 7 บัญชี
   รหัสผ่านจะแสดงบนจอ ให้จดไว้ (รันซ้ำได้ ระบบจะตั้งรหัสผ่านใหม่)
5. พิมพ์ `npm run dev` แล้วเปิด http://localhost:3002/login

ถ้าย้ายไปใช้โครงการ Supabase ใหม่: รันไฟล์ใน `supabase/migrations/` ทีละไฟล์ตามลำดับเลขหน้าชื่อไฟล์
ใน SQL Editor แล้วรัน `supabase/seed_test_data.sql` ถ้าต้องการข้อมูลทดสอบ

## บัญชีผู้ใช้และสิทธิ์ (บทที่ 3)

- เข้า `/app/...` ได้เมื่อล็อกอิน บัญชีได้รับอนุมัติ ยืนยันตัวตน 2 ขั้นแล้ว (ถ้าบทบาทบังคับ) และรหัสผ่านยังไม่ครบอายุ
- บทบาทที่บังคับ 2 ขั้นตั้งแต่ต้น: ผู้ดูแลระบบ เจ้าคณะ รองเจ้าคณะ เจ้าหน้าที่การเงิน
  (ปรับได้ที่ `/app/admin/settings`) ต้องมีแอป Authenticator บนมือถือ
- ผู้ขอบัญชีกรอกที่ `/request-account` ผู้ดูแลระบบหรือหน่วยเหนืออนุมัติที่ `/app/admin/users`
- ทบทวนสิทธิ์ประจำปีที่ `/app/admin/access-review`
- เมนูที่แต่ละบทบาทเห็น แก้ได้ที่ `src/lib/auth/config.ts` (ROLE_MENUS)
- ผู้ดูแลระบบคนแรก: ใช้บัญชีทดสอบ `test.admin@example.com` อนุมัติบัญชีจริงของท่าน
  แล้วกด "เพิ่มบทบาท" > ผู้ดูแลระบบ จากนั้นจึงระงับบัญชีทดสอบ
- การส่งอีเมล (ลืมรหัสผ่าน) ใช้ระบบอีเมลของ Supabase ซึ่งส่งได้จำกัด เหมาะกับการทดสอบเท่านั้น
  ก่อนใช้งานจริงต้องตั้งค่า SMTP ของหน่วยงานใน Supabase

## โครงสร้างโดยย่อ

- `src/lib/site.ts` ชื่อเว็บและรายการเมนูทั้งหมด (แก้ที่นี่ที่เดียว)
- `src/app/globals.css` โทนสีและขนาดตัวอักษรของทั้งเว็บ
- `src/app/(public)/` หน้าโซนสาธารณะ ไม่ต้องล็อกอิน
- `src/app/app/` หน้าโซนพื้นที่ทำงาน (เส้นทาง /app/...)
- `src/components/` ชิ้นส่วนที่ใช้ซ้ำ
- `src/lib/org-units.ts` กติกาของเขตปกครอง (ระดับ นิกาย การตรวจไฟล์นำเข้า)
- `src/lib/supabase/` ตัวเชื่อมฐานข้อมูล (`server.ts` ใช้เป็นหลัก ทำงานในนามผู้ใช้)
- `src/lib/auth/` ล็อกอิน สิทธิ์ ด่านตรวจของหน้า และค่าตั้งด้านบัญชี
- `src/proxy.ts` ด่านแรก: ยังไม่ล็อกอินเข้า /app ไม่ได้
- `scripts/seed-test-users.mjs` สร้างบัญชีทดสอบ
- `supabase/migrations/` ไฟล์เปลี่ยนโครงสร้างฐานข้อมูล (รันตามลำดับ ห้ามแก้ไฟล์ที่รันไปแล้ว)
- `supabase/seed_test_data.sql` ข้อมูลทดสอบ
- `supabase/seed_civil_areas.sql` จังหวัด อำเภอ ตำบล รหัสไปรษณีย์ ทั้งประเทศ (รันครั้งเดียวหลัง migration ของบทที่ 9)
