# ติดตามระบบ

## 1. บันทึกข้อผิดพลาด (ทำงานอัตโนมัติ)

- ข้อผิดพลาดฝั่งเซิร์ฟเวอร์ทุกครั้ง (หน้าเว็บ Server Action API) ถูกบันทึกโดย `src/instrumentation.ts` (onRequestError) ลงตาราง `app_error_logs`
- ข้อผิดพลาดฝั่งเบราว์เซอร์ที่ทำให้หน้าแสดง "ขออภัย ระบบขัดข้องชั่วคราว" ถูกส่งมาบันทึกด้วย (`src/components/error-view.tsx`) จำกัด 30 ครั้งต่อนาทีต่อเครื่อง
- บันทึกเฉพาะ: เวลา ฝั่ง ชนิดงาน หน้าเว็บ (ตัดส่วน ?คำค้น ทิ้ง) ข้อความ รหัสอ้างอิง (digest) ไม่บันทึกข้อมูลที่ผู้ใช้กรอก ทั้งระบบรับไม่เกิน 200 รายการต่อนาที
- ผู้ใช้เห็น **รหัสอ้างอิง** บนหน้าข้อผิดพลาด ให้แจ้งรหัสนี้มา ผู้ดูแลค้นได้ที่ ผู้ดูแลระบบ > **สถานะระบบ**
- รายละเอียดเต็ม (stack trace) ดูได้ที่ Vercel > Project > Logs ค้นด้วยรหัสอ้างอิงเดียวกัน

## 2. แจ้งเตือนผู้ดูแลระบบ

| เหตุการณ์ | ช่องทาง | ตั้งค่า |
|---|---|---|
| ข้อผิดพลาดใน 15 นาทีถึงเกณฑ์ (ค่าเริ่มต้น 10 รายการ) | แจ้งเตือนในเว็บถึงผู้ดูแลระบบทุกคน ไม่เกินชั่วโมงละครั้ง | ค่าตั้ง `ops_error_alert_threshold` ที่หน้า บทบาทและค่าตั้ง (0 = ปิด) |
| เว็บหรือฐานข้อมูลล่ม (เว็บเองแจ้งไม่ได้) | อีเมล (และ LINE ถ้าตั้ง) จากบริการเฝ้าระบบภายนอก | ข้อ 3 |
| การสำรองข้อมูลรายคืนล้มเหลว | อีเมลจาก GitHub ถึงเจ้าของ repository (ค่าเริ่มต้นของ GitHub Actions) | GitHub > Settings > Notifications > Actions |

## 3. ตั้งบริการเฝ้าระบบภายนอก (UptimeRobot แผนฟรี ทำครั้งเดียว)

1. สมัคร uptimerobot.com ด้วยอีเมลของผู้ดูแลระบบ (ควรเป็นอีเมลกลางของหน่วยงาน)
2. **Add New Monitor**: Monitor Type = HTTP(s) - Keyword, URL = `https://ที่อยู่เว็บ/api/health`, Keyword = `"status":"ok"` (Alert when keyword not exists), Interval = 5 minutes
3. Alert Contacts: ใส่อีเมลผู้ดูแลระบบอย่างน้อย 2 คน (เพิ่ม LINE Notify หรือ Telegram ได้ถ้าต้องการ)
4. ทดสอบ: กด Pause แล้ว Resume หรือเปลี่ยน Keyword ชั่วคราวให้ผิด ต้องได้อีเมลแจ้งภายในไม่กี่นาที
5. ทำซ้ำอีก 1 monitor สำหรับชุดทดสอบได้ (ไม่บังคับ)

`/api/health` ตอบ 200 เมื่อเว็บและฐานข้อมูลทำงาน, 503 เมื่อฐานข้อมูลไม่ตอบใน 5 วินาที ไม่คืนข้อมูลภายในใด ๆ และไม่ถูกแคช

## 4. งานประจำของผู้ดูแลระบบ

| ความถี่ | งาน |
|---|---|
