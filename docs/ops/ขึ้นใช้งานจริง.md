# ขั้นตอนขึ้นใช้งานจริง (ทำครั้งเดียว ตามลำดับ)

ทำเครื่องหมาย [x] เมื่อเสร็จแต่ละข้อ ข้อที่ต้องใช้ค่าลับ (รหัสผ่านฐานข้อมูล Secret key) ให้ผู้ดูแลระบบทำเองบนเครื่องของหน่วยงาน ห้ามส่งค่าลับทางแชต

## ก. เตรียมชุดทดสอบ (staging)

- [ ] 1. โครงการ Supabase ชุดทดสอบ `registry-staging` (รหัส zqdzfugqvmxwoteiptob สร้างแล้วในบทที่ 32 ยังว่าง) ตั้งรหัสผ่านฐานข้อมูลที่ Project Settings > Database > Reset database password
- [ ] 2. ตั้ง GitHub Secrets (repository > Settings > Secrets and variables > Actions) ตาม [สำรองและกู้คืน.md](สำรองและกู้คืน.md) ข้อ 1
- [ ] 3. GitHub > Actions > **สำรองข้อมูลรายวัน** > Run workflow (สำรองชุดใช้งานจริงครั้งแรก ตอนนี้ยังมีแต่ข้อมูลทดสอบ)
- [ ] 4. GitHub > Actions > **กู้คืนลงชุดทดสอบ** > Run workflow พิมพ์ `RESTORE-STAGING` = ซ้อมกู้คืนจริงครั้งแรก และได้ชุดทดสอบที่มีโครงสร้างและข้อมูลทดสอบเหมือนชุดใช้งานจริง (บันทึกผลในตารางท้าย [สำรองและกู้คืน.md](สำรองและกู้คืน.md))
- [ ] 5. ตั้ง Vercel ตาม [deploy.md](deploy.md) ข้อ 2 (Preview ชี้ชุดทดสอบ) แล้วเปิดเว็บชุดทดสอบ ต้องเห็นแถบ "ชุดทดสอบ" ทุกหน้า

## ข. เตรียมชุดใช้งานจริง (production)

- [ ] 6. Supabase ชุดใช้งานจริง: Authentication ตาม [deploy.md](deploy.md) ข้อ 3 (URL, รหัสผ่าน 12 ตัว, SMTP, แม่แบบอีเมล)
- [ ] 7. **ล้างข้อมูลทดสอบ**: SQL Editor ของชุดใช้งานจริง > รัน `scripts/ops/remove-test-data-preview.sql` ตรวจรายการ "จะลบ" และ "เก็บไว้" แล้วรัน `scripts/ops/remove-test-data.sql`
  - ลบ: บัญชี test.*@example.com, เขตปกครอง TEST-*, ข้อมูลงานทุกระบบ, ประเภทตำแหน่ง จศป. TEST-, ประวัติการแก้ไขของข้อมูลทดสอบ, ตัวนับเลขที่
  - เก็บ: ค่าตั้ง บทบาท เมนู ประเภทตำแหน่ง ชนิดคำขอ แบบฟอร์ม ศ. เขตการปกครองบ้านเมือง รายวิชา หน่วยการเรียน บทเรียน ข้อสอบ ปีการศึกษา หมวดงบ นโยบายความเป็นส่วนตัว
  - สคริปต์หยุดเองถ้าพบเขตปกครองหรือบัญชีจริงแล้ว (กันรันซ้ำหลังเริ่มใช้งาน)
- [ ] 8. **สร้างผู้ดูแลระบบคนแรก** บนเครื่องผู้ดูแล: สร้างไฟล์ `.env.production.local` (ค่าของชุดใช้งานจริง ห้าม commit) แล้วรัน
  `node --env-file=.env.production.local scripts/ops/create-admin.mjs อีเมลจริง "ชื่อ" "นามสกุล" --site=https://ที่อยู่เว็บ`
  ส่งลิงก์ตั้งรหัสผ่านที่แสดงให้เจ้าของบัญชีทางช่องทางส่วนตัว เข้าสู่ระบบครั้งแรกตั้งยืนยันตัวตน 2 ขั้น
- [ ] 9. ตั้ง Vercel Production ตาม [deploy.md](deploy.md) ข้อ 2 แล้ว deploy กิ่ง main ตรวจ `/api/health`
- [ ] 10. ตั้งบริการเฝ้าระบบตาม [ติดตามระบบ.md](ติดตามระบบ.md)

## ค. นำเข้าข้อมูลจริง (ผู้ดูแลระบบ > นำเข้าข้อมูลจริง)

ลำดับบังคับ เพราะข้อมูลขั้นหลังอ้างถึงขั้นก่อน ทุกขั้นตรวจทั้งไฟล์ ผิดแถวเดียวไม่บันทึก และดาวน์โหลดรายงานแถวที่ผิดเป็น Excel ได้

| ขั้น | ข้อมูล | ที่นำเข้า | ข้อควรระวัง |
|---|---|---|---|
| 1 | เขตปกครองคณะสงฆ์ (ส่วนกลาง > ภาค > จังหวัด > อำเภอ > ตำบล แยกนิกาย) | ผู้ดูแลระบบ > เขตปกครอง > นำเข้า Excel | เขตการปกครองบ้านเมือง 77 / 928 / 7,436 มีอยู่แล้ว |
| 2 | สถานที่ (วัดก่อน แล้วสำนักเรียน สำนักศาสนศึกษา สถานศึกษา องค์กร) | ทะเบียนสถานที่ > นำเข้า (ทีละประเภท) | สำนักต้องระบุรหัสวัดที่ตั้ง นิกายต้องตรงกับเขต |
| 3 | บุคคล แล้วตำแหน่ง | บุคลากร > นำเข้า / นำเข้าข้อมูลจริง > นำเข้าตำแหน่ง | ตำแหน่งหาบุคคลด้วยเลขประจำตัว (แม่นยำสุด) หรือชื่อ + ฉายา + นามสกุล |
| 4 | สนามสอบ | นำเข้าข้อมูลจริง > นำเข้าสนามสอบ | ผูกกับรหัสสถานที่ตั้ง ประธานและผู้รับข้อสอบกรอกที่หน้าสนามสอบ |
| 5 | ผู้ใช้ | นำเข้าข้อมูลจริง > นำเข้าผู้ใช้ | ครั้งละไม่เกิน 300 บัญชี ผู้ใช้ตั้งรหัสผ่านเองที่ ลืมรหัสผ่าน (ต้องตั้ง SMTP แล้ว) |

ไฟล์ที่ผู้กรอกส่งมามีข้อมูลส่วนบุคคล เก็บในเครื่องของหน่วยงาน ลบสำเนาที่ไม่ใช้แล้ว ห้ามส่งในกลุ่มสนทนาสาธารณะ

## ง. ก่อนเปิดให้ผู้ใช้

- [ ] 11. ผู้ดูแลระบบกรอกเนื้อหาที่ต้องมาจากระเบียบจริง: นโยบายความเป็นส่วนตัว อายุการเก็บข้อมูล รายการเอกสารของคำขอ ช่องลงนามท้ายบัญชี ศ. วงเงินอนุมัติงบ ข้อมูลหน้าติดต่อเรา ผู้รับข้อความแต่ละหัวข้อ
- [ ] 12. ตั้งปีการศึกษาปัจจุบันและปีงบประมาณ (ผู้ดูแลระบบ > บทบาทและค่าตั้ง / งบประมาณ > ตั้งค่า)
- [ ] 13. ตรวจหน้า ผู้ดูแลระบบ > สถานะระบบ: ชุด = ใช้งานจริง ฐานข้อมูลทำงานปกติ ไม่มีข้อผิดพลาด
- [ ] 14. เริ่มแผนนำร่องตาม [แผนเปิดใช้.md](../แผนเปิดใช้.md)
